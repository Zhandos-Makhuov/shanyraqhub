Интерфейс на ru/kz/en. Владелец общается **на русском** — отвечать по-русски, термины кода оставлять как есть.

## Стек и команды
- Vite 8 + React 19 + TypeScript + Tailwind 4, SPA без роутера (`activeTab` в контексте). Пакетный менеджер: bun.
- `bun run dev` (порт 3000), `bun run lint` (= `tsc --noEmit`), `bun run build`.
- Режим данных: `VITE_DATA_SOURCE=demo|live` (по умолчанию `demo`). Боевую сборку проверять: `VITE_DATA_SOURCE=live npx vite build` — в `dist` не должно быть демо-имён.
- Тесты схемы БД на локальном PostgreSQL 16: `PGHOST=… PGPORT=… PGUSER=postgres supabase/tests/run-local.sh` (сейчас **90 проверок, все проходят**).
- После правки достижений/уровней/магазина: `npx tsx scripts/generate-seed.ts > supabase/seed.sql`.
- Браузерные проверки — Playwright (`require('playwright')`, Chromium предустановлен). Тестовые скрипты лежат вне репозитория (scratchpad), пишутся заново под задачу.

## Принятые решения
### Безопасность и права
- Роли: member < organizer < moderator < admin < super_admin (роль **organizer сохраняем**, сайт её использует). Админ назначает роли только ниже своей; себе менять нельзя; последнего super_admin не понизить. Коины корректирует только admin+, не себе, баланс не в минус.
- Отмечать посещения может **только персонал (organizer+)**, и только других.
- Каждый посетитель начинает как **«Новый участник»** (member, бронза, 0 XP/0 коинов). Переключатель тестовых аккаунтов — только в демо и только в dev (или `VITE_DEMO_MODE=true`).
- Чаты: **никаких заявлений про E2EE** — честные надписи «Закрытый чат», «Доступ: …». Комната «Совет модераторов» скрыта от участников. Настоящая защита — RLS по ролям в базе.
- Уведомления видны только своему владельцу; журнал аудита сохраняется.

### Геймификация
- Все награды идут через `grantRewardOnce` (уникальный ключ — без повторных выплат; дневные лимиты для форума/отзывов). На сервере аналог — `private.grant_reward` + `reward_ledger` с `idempotency_key`; клиент не может менять балансы.
- **Книга засчитывается** (+50 XP/+30 коинов и книжные достижения) только если прочитана, есть рецензия **≥100 символов**, и не более **одной книги в неделю**. Фальшивую рецензию по умолчанию убрали. На сервере дата прочтения ставится базой.
- **Серии**: дни подряд и **недели подряд** (пн–вс, хотя бы одно действие). В карточке «Серия участия» главное — недели.
- **Уровни (XP)**: Серебро 300, Золото 1000, Платина 2500, Титан 5000, Тәңір 9000 (≈ год для активного участника). Уровень всегда пересчитывается из XP.
- **Бонус коинов за посещение растёт с уровнем**: Серебро +10%, Золото +15%, Платина +20%, Титан +25%, Тәңір +30% (40 → 44…52).
- **34 достижения** (30 автоматических, 4 выдаёт модератор: выступление Til-Talk, забег Tarlan, призовое место Zerde, марафон 30 дней чтения). Отдельные карточки (не ступени). Каждому из 7 направлений — «5 посещений» (150 XP/80). Серии дней (7) и недель (4/12/26). Для ведущих: первая встреча, 10 встреч, «Любимый спикер» (встреча засчитывается при ≥3 подтверждённых участниках; рейтинг — ≥3 отзыва со средним 4,5+). Достижения навсегда, но **admin может отозвать** с причиной (награда списывается, баланс не в минус, аудит, уведомление, не открывается снова; повторная ручная выдача снимает отзыв).

### Мероприятия и данные
- Регистрация проверяет места/дату/дубли в логике; прошедшие события — «Регистрация закрыта». На главной — только будущие события.
- Демо-события сдвигаются относительно дня первого открытия (3 прошедших, 1 сегодня, 2 будущих).
- **Демо и боевые данные строго разделены** (`VITE_DATA_SOURCE`). В live-сборке демо-модуля нет. Production должен работать в `live`.
- **Статистика только из реальных данных** (`communityStats.ts`); прежние завышающие формулы и вписанные цифры удалены. Пусто — «—».

### Интерфейс и прочее
- Короткие подписи вкладок: Достижения, Книги, Магазин, Управление; в нижнем меню «События».
- PWA: service worker network-first для страниц, правильные иконки 192/512 + maskable.
- Удалены неиспользуемые зависимости шаблона AI Studio (Gemini, express, dotenv); пакет называется `shanyraq-hub`.
