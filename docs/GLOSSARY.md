# Словарь терминов SHANYRAQ HUB

Простые объяснения слов, которые встречаются в работе над сайтом. Составлен 22.11.2026 для владельца.

## Код и версии
- **Репозиторий (GitHub)** — папка проекта в интернете, где хранится весь код сайта и вся история изменений. Наш — `Zhandos-Makhuov/shanyraqhub`.
- **Ветка (branch)** — отдельная копия кода, где можно работать, не трогая основную. Как черновик рядом с чистовиком.
- **`main`** — главная ветка, «чистовик». Из неё автоматически собирается боевой сайт.
- **Рабочая ветка** (`claude/sleepy-brown-4zolp6`) — «черновик» Claude, где делаются все этапы.
- **Коммит** — сохранённая порция изменений с описанием, точка в истории (короткий номер вроде `25f56fb`).
- **Пуш (push)** — отправка коммитов в GitHub.
- **Слияние (merge)** — перенос изменений из рабочей ветки в `main`; после него они попадают на боевой сайт.
- **Fast-forward** — самое простое слияние: `main` просто «догоняет» рабочую ветку, конфликтов нет.
- **Конфликт** — одно и то же место кода изменено по-разному в двух ветках; нужно вручную решить, что оставить.
- **Diff** — список изменений: какие строки удалены, какие добавлены.
- **Откат (revert)** — возврат сайта к прошлой версии, если новая не понравилась.

## Сайт и где он работает
- **Боевой сайт / production / прод** — настоящий сайт для участников: https://shanyraqhub.pages.dev.
- **Деплой** — выкладка новой версии сайта в интернет.
- **Cloudflare Pages** — сервис, который хранит и показывает сайт; сам собирает его из GitHub.
- **Превью (Preview) Cloudflare** — тестовая ссылка на рабочую ветку. Наше превью подключено к **боевой** базе — там нельзя ничего делать.
- **Демо** (https://shanyraq-demo-auto.pages.dev) — копия сайта с выдуманными участниками и без базы. Безопасна для просмотра.
- **Демо-режим / боевой (live) режим** — сайт работает на выдуманных данных (демо) или на настоящей базе (live).
- **Сборка (build)** — превращение кода в готовые файлы сайта.
- **PWA** — сайт, который можно установить на телефон как приложение (иконка на экране).
- **Service worker** — небольшая программа в браузере, помогает сайту работать как приложение и получать push-уведомления.
- **Автообновление** — открытая страница сама перезагружается, когда вышла новая версия.

## База данных (Supabase)
- **Supabase** — сервис, где хранится база (участники, встречи, книги, коины), там же вход и уведомления.
- **Боевая база** — настоящие данные. **Тестовая база** — точная копия устройства для проверок, данные выдуманные.
- **Таблица** — как лист Excel в базе (например, таблица книг или записей на встречи).
- **Схема** — устройство базы: какие таблицы и колонки.
- **Миграция** — изменение устройства базы (например, новый статус «Хочу прочитать»). Новые функции, которым нужны новые данные, требуют миграции и согласия владельца.
- **RLS (Row Level Security)** — правила доступа прямо в базе: кто какие строки может видеть и менять.
- **RPC / серверная функция** — действие, которое выполняет сама база, а не браузер (например, начисление коинов — так их нельзя подделать).
- **Edge Functions** — маленькие программы на сервере Supabase: push-уведомления, Telegram-бот, вход через Telegram.
- **pg_cron** — расписание внутри базы («каждые 5 минут разослать напоминания»).
- **Realtime** — мгновенные обновления: новое сообщение в чате появляется без перезагрузки.

## Доступы и безопасность
- **Токен (API-токен)** — длинный секретный пароль для программы с ограниченным доступом. Вводится в защищённую форму, не в чат.
- **Секрет** — любая тайная строка, которую нельзя показывать и класть в код.
- **Publishable key** — публичный ключ базы; он и так виден в коде сайта, это нормально.
- **service_role** — «главный ключ» базы; только на сервере, никогда в сайте.
- **SMTP** — почтовый сервер для писем (подтверждение почты, восстановление пароля). При входе через Telegram не нужен.
- **Management API** — способ обращаться к Supabase и Cloudflare через токен.

## Telegram
- **Бот** (`@shanyraq_hub_bot`) — аккаунт-программа в Telegram: отвечает и присылает уведомления.
- **Mini App** — сайт, открытый внутри Telegram кнопкой «Открыть клуб»; вход автоматический.
- **Вебхук (webhook)** — адрес, на который Telegram сообщает боту о новых сообщениях.

## Проверки
- **Lint / проверка типов** — автоматическая проверка кода на ошибки до запуска.
- **Автопроверки / e2e-тесты** — программа сама открывает сайт, нажимает кнопки и сверяет результат (`e2e/`).
- **Playwright** — инструмент, который управляет браузером для таких проверок.
- **GitHub Actions / CI** — GitHub сам запускает проверки после каждого изменения: ✅ — всё прошло, ❌ — что-то сломалось. Смотреть: https://github.com/Zhandos-Makhuov/shanyraqhub/actions
- **QA** — проверка качества: всё ли работает и удобно.
- **Аудит** — большая проверка перед важным шагом (например, перед слиянием в `main`).

## Интерфейс
- **Модальное окно** — окно поверх страницы с затемнением (подробности встречи, книги, форма).
- **Шторка (bottom sheet)** — окно, выезжающее снизу (меню «Тағы»).
- **px (пиксели)** — единица ширины экрана: 320–430 px — телефоны, 768 — планшет, 1280 — компьютер.
- **Адаптивность (responsive)** — сайт подстраивается под ширину экрана.
- **Breakpoint** — ширина, на которой вид меняется (например, от 480 px книги в 3 колонки).
- **Горизонтальная прокрутка / overflow** — что-то шире экрана, страницу можно «тянуть» вбок; ошибка вёрстки.
- **Viewport** — видимая часть экрана.
- **Безопасные зоны (safe area)** — вырез камеры и полоска жестов на телефоне; кнопки не должны туда попадать.
- **Пропорции 2:3 и 3:4** — соотношение ширины и высоты обложки; 3:4 чуть ниже, края фото могут обрезаться.
- **Доступность (accessibility)** — удобство для людей с ограничениями (например, незрячих).
- **Скринридер** — программа, которая читает экран вслух.
- **Фокус** — какой элемент сейчас выбран клавиатурой (Tab).
- **aria-label / aria-labelledby** — скрытые подписи для скринридеров.

## Процесс
- **Phase (этап)** — порция работы по одному разделу (2.2 — книги, 2.3 — профиль).
- **Roadmap** — план этапов на будущее.
- **ТЗ** — техническое задание: что нужно сделать.
- **Бэклог** — список отложенных задач и замечаний (`docs/BACKLOG.md`).
- **Minor / QA / Backlog** — метки замечаний: «мелочь», «нужно проверить», «идея на будущее».
