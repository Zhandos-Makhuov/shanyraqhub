## 7. Архитектурные решения
1. **Поиск на клиенте.** Форум уже загружается целиком в снимок (F-31), поэтому фильтрация в памяти — мгновенная и без нагрузки на базу (требование ТЗ). Ограничение записано как N-9.
2. **Переход из уведомления без изменения backend.** Серверный триггер уже пишет `meta.topic_id`; RLS даёт участнику читать свои уведомления целиком. Добавлено только чтение поля. Push и Telegram не менялись.
3. **Намерение навигации** — тот же приём, что у встреч (`navIntent.ts`): модульная переменная + событие окна. Работает и когда форум ещё не открыт (забирается при монтировании), и когда уже открыт (событие).
4. **Фильтры сбрасываются при переходе из уведомления** — иначе нужная тема может быть скрыта фильтром.
5. **Двойная отправка** — `useRef`, а не `useState`: состояние обновляется асинхронно, и два быстрых нажатия успевали пройти проверку.
6. **Enter = новая строка** (а не отправка) — на телефоне Enter нужен для абзацев; отправка — кнопкой или Ctrl/⌘+Enter на компьютере.

1. Форум → поиск «idioms» → должна остаться одна тема; «Сбросить» — все темы.
2. Открыть тему → набрать 3–4 строки с Enter → поле растёт, клавиатура не закрывает кнопку «Жауап беру».
3. Отправить ответ → поле очистилось, ответ с абзацами.
Переход из уведомления на телефоне в демо проверить нельзя (ответ в вашу тему должен написать другой участник) — проверено в e2e и на тестовой базе.
