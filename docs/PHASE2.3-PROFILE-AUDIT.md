| Кто | Видит | Может менять |

| **Admin+** | + телефоны всех (`contacts_read`), история коинов всех, журнал аудита | роли ниже своей, коины, выдача/отзыв достижений; super_admin — и себе |

Непубличные данные:
- **Почта** — в `profiles` нет, только `auth.users`; показывается лишь самому участнику. ✅
- **Телефон** — RLS: владелец и admin+. В интерфейсе нигде не выводится. ✅
- **Внутренние идентификаторы** — UUID нигде не показываются ✅; **но** во вкладке посещений выводится служебный id направления (`books`, `sport`) — исправить на название (🟢).
- **Telegram-почта** `tg-…@telegram.invalid` — в шапке скрыта ✅.
- `telegram_handle` виден всем — это поле, которое участник сам заполняет как публичный контакт; оставить, но подписать в форме «видно всем» (🟢, решение).

**Коины — предложение модели (нужно решение владельца):**
- Сейчас коины фактически **публичны**: RLS `balances_read using (true)`, рейтинг показывает и сортирует по коинам всех.
- **Вариант A (рекомендую на этом этапе)** — оставить как есть (коины — игровая валюта, как XP, уже публичны в рейтинге); в чужом профиле не показывать (как сейчас). 🟢 ничего менять не нужно.
- **Вариант B** — сделать коины личными: RLS `user_balances` → свои + admin+; XP вынести в публичное представление; из рейтинга убрать сортировку «Коины». 🟠 миграция + RLS + правка рейтинга.

## 6. Что работает частично
- **Роль** показывается, но сырым кодом (`SUPER_ADMIN`, `MODERATOR`) — не переведена.
- **Даты** в книгах, посещениях, отзывах, «Қауымдастыққа қосылды 2024-01-15» — в формате `YYYY-MM-DD` (в остальных разделах уже `formatShortDate` по языку).
- **Книги**: список есть, но без обложек, оценка у «читаю», нет связи с библиотекой (открыть книгу).
- **Посещения**: список есть, вместо направления — служебный id.
- **Отзывы**: после отправки окно чужого профиля показывает старые данные (`selectedUserModal` — снимок объекта, `AppContext` его не обновляет) — новый отзыв виден только после повторного открытия.
- **Форма редактирования**: состояние берётся из `currentUser` один раз — при смене аккаунта (демо) или обновлении данных форма может показать старые значения; телефон не редактируется.
- **Вкладки** на телефоне — горизонтальная лента; на 320 px активная вкладка прокручивается так, что первая обрезана («…н кітаптарым (4)»), без признака прокрутки.
- **Талисман**: подпись `badgeTitle` у части предметов не переведена.

| **Таблица `profile_showcase(user_id, position 1–3, achievement_id)`** — PK `(user_id, position)`, unique `(user_id, achievement_id)`, FK на `user_achievements(user_id, achievement_id)` с `on delete cascade`; RLS: читают все, пишет только владелец; при отзыве достижения — удаление (FK/триггер на `achievement_revocations`) | да | да, на уровне базы | **рекомендую** |

Без миграции витрину, видимую другим, сделать **нельзя**.

## 11. Acceptance Criteria
1. Ни в одном виде профиля нет почты, телефона, UUID, служебных id направлений, `@telegram.invalid`.
2. Роль, даты, названия направлений, предметов, аспектов — на языке интерфейса (kz/ru/en), нет вписанных строк.
3. Свой и чужой профиль на 320–1280 px без горизонтальной прокрутки; длинные имена/названия переносятся; кнопки ≥ 44 px.
4. Коины видны только в своём профиле (и в рейтинге — по выбранной модели).
5. Чужой профиль: `role="dialog"` + `aria-labelledby`, закрытие крестиком (всегда виден), фоном и Escape; после отзыва — сразу виден новый отзыв.
6. Битое фото → инициалы, ничего не вылезает.
7. Книга «читаю» — без оценки; клик по книге открывает её в библиотеке; полка не дублируется.
8. Отзывы о человеке — только существующие `peer_reviews`; скрытые не видны участникам.
9. Редактировать можно только свой профиль (UI + RLS); форма показывает актуальные данные.
10. В live клиент не начисляет награды; XP/коины/достижения не меняются от действий профиля, кроме отзыва (сервер).
11. Демо и live работают; в live-сборке нет демо-имён; e2e и CI зелёные.
12. Витрина (если согласована): ≤3, только полученные, исчезает при отзыве — проверено тестами БД.

## 12. Тест-план
**Ширины:** 320, 360, 375, 390, 430, 768, 1024, 1280 (телефон — `isMobile`, `hasTouch`); языки kz (основной) + ru/en выборочно.

| Проверка | Как |
|---|---|
| Нет горизонтальной прокрутки, свой профиль, каждая вкладка/блок | e2e, все 8 ширин |
| Чужой профиль: окно, крестик видим после прокрутки, Escape, фон | e2e 320/390/1280 |
| Нет почты, телефона, UUID, `books`/`sport` как текста | e2e: регэкспы по тексту `main` и окна |
| Роль и даты переведены (kz/ru/en) | e2e 390 |
| Длинное имя (80 символов), длинное био, длинное название книги | демо-данные в тесте (localStorage) |
| Битая ссылка на фото → инициалы | e2e (внешние запросы уже блокируются) |
| Отзыв: появляется сразу, нельзя себе, 4-й в сутки — без награды | e2e демо + live тестовая |

| Форма на 320×568 и с клавиатурой | e2e + ручная проверка на телефоне владельца |
| Витрина (если будет) | тесты БД + e2e |
