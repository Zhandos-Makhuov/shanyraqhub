## 2. C-23a — отмена записи вживую для всех участников
- **Причина.** RLS (решение C-21) скрывает чужие отменённые записи, а Realtime соблюдает RLS. Поэтому отмену вживую видели только организатор и модераторы.
- **Отклонено:** «тронуть» строку встречи. Тогда `events_audit` писал бы строку журнала аудита на каждую запись.
- **Решение.** Миграция `20261125000002_c23a_registration_broadcast.sql`:
  - триггер `registrations_broadcast` (после смены статуса или удаления записи) вызывает `realtime.send({event_id}, 'registrations_changed', 'shq-events', private=true)`;
  - ошибка отправки не мешает записи или отмене;
  - политика `shq_events_broadcast_read` на `realtime.messages` — только `authenticated`;
  - клиент (`live.subscribeLive`) слушает закрытый канал и перезагружает данные через RLS.
- **Проверки:**
  - серверные +3: подсказка отправляется при отмене, политика только для вошедших, триггер есть;
  - live: отмена чужой записи у участника видна вживую (раньше не проходило);
  - гость: `CHANNEL_ERROR: Unauthorized`, 0 сообщений.

## 3. S-3a — прочитанная книга не возвращается в «Читаю»
- **Сервер:** триггер `user_books_no_reopen` (before update of status) → `book_already_completed`. Прямое изменение `status` через API и так запрещено (grant только на `rating`, `review`), так что путь один — `save_user_book`, и триггер его закрывает.
- **Сайт:**
  - в окне «Өзгерту» прочитанной книги кнопка «Оқып жатырмын» выключена, рядом пояснение (kz/ru/en);
  - то же при добавлении книги, которая уже прочитана на своей полке;
  - в демо — та же проверка;
  - ошибка сервера переводится (`liveErrBookCompleted`).
- Правило зачёта (одна книга в неделю, рецензия ≥100) и награды не менялись.
- **Проверки:** серверные +2, API +2 (403, книга осталась прочитанной), e2e 3 (kz, ru; «Читаю → Прочитана» по-прежнему можно).

## 4. S-1/S-2 — тема после чужих ответов
- **Сервер:** триггер `forum_topics_author_guard` (before update/delete).
  - Ограничен только автор, действующий над своей темой. Модераторы и системные операции (без вошедшего пользователя, например удаление аккаунта) не ограничены.
  - Удаление запрещено, если есть ответы других.
  - Правка запрещена, если меняются `title` или `content`. Служебные обновления строки проходят.
- **Сайт:** уже не предлагал этих действий (Phase 2.4). Теперь гонка N-13 (чужой ответ пришёл, пока открыто окно правки) получает понятное сообщение `liveErrTopicHasReplies`.
- **Проверки:**
  - серверные +5: без чужих ответов править можно; после — правка заголовка, правка текста и удаление отклоняются, автор может отвечать; модератор удаляет;
  - API +5: 403 на правку и удаление, чужой ответ на месте.
