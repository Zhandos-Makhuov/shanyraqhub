## 1. Executive Summary
Раздел «Форум және Чаттар» — один экран `ForumAndChatsView.tsx` (543 строки) с двумя частями: **«Ашық талқылаулар»** (темы и ответы) и **«Жабық бөлмелер»** (чаты по ролям). Базовые сценарии работают: список тем, чтение темы, ответ, голос «полезно», создание темы, чат. Сервер защищён хорошо: награды, дневные лимиты, запрет голоса за себя и модерационные поля (закрепить/закрыть/скрыть) охраняет база (триггеры + RLS).

Главные проблемы — в интерфейсе, а не в защите:
1. **Создание темы в направлении «Нетворкинг» (и любом новом направлении админа) невозможно** — для них нет раздела форума; сервер отклоняет, пользователь видит невнятное «Енгізілген деректерді тексеріңіз», окно закрывается, текст теряется (Verified на тестовой базе).
2. **На телефонах 320–390 px кнопка «Жауап беру» обрезана** (на 320 px скрыто 71 px из ~95) — Verified.
3. **Темы и комнаты нельзя открыть с клавиатуры** (кликабельные `div`) — Verified.
4. Любая ошибка сервера при создании темы/ответа **теряет набранный текст** (форма очищается до ответа сервера) — Verified/Code-confirmed.
5. Абзацы в постах **склеиваются**, длинные слова/ссылки **обрезаются** — Verified.
6. Роли (`MEMBER`, `ORGANIZER`) и даты (`20.11.2026 02:29`, в демо `2024-11-08`) — **не локализованы**.
7. В интерфейсе **нет модерации** (закрепить/закрыть/скрыть/удалить/жалоба), хотя база это поддерживает; автор не может править/удалить свою тему.

Critical (P0) — не найдено. Найдено **32 замечания** (F-01…F-32): High — 5, Medium — 14, Low — 13; плюс **2 Security concerns** (S-1, S-2, низкий риск, нужно решение владельца) и список Future-идей (раздел 17).

## 4. Current forum architecture
- **Навигация:** вкладка `forum` (десктоп — верхнее меню; телефон — «Тағы» → «Форум және Чаттар»). Внутри — сегментный переключатель «Ашық талқылаулар / Жабық бөлмелер» (локальное состояние, не URL).
- **Раскладка:** `lg` (≥1024 px) — две колонки (список 5/12, тема 7/12); ниже 1024 px (включая планшет 768) — одна колонка: список → тема с кнопкой «Барлық тақырыптарға оралу».
- **Данные (live):** весь форум загружается в общем снимке при входе: все темы (`created_at desc`), все ответы, все голоса, комнаты, последние 500 сообщений. После любого действия — полная перезагрузка снимка. Realtime: новые ответы и сообщения чата → обновление; новые темы — нет.
- **Раздел темы:** при создании выбирается **направление** (`activeDirections()` + «general»), и это же значение пишется как `category_id`. Разделы форума — отдельная таблица `forum_categories` (7 строк, без `networking`).
- **Права (база):** читать — все вошедшие (скрытое — автор и модератор+); писать — свои; ответ — только в незакрытую и нескрытую тему; голос — свой, не за себя (триггер); правка своих текстов — автор; закрепить/закрыть/скрыть — только модератор+ (триггер `guard_forum_moderation`); удалить тему/ответ — автор или модератор+. Чаты: читать/писать — по `min_role` комнаты; скрыть сообщение — модератор+.
- **Награды:** только сервер (в live клиент не начисляет).

## 5. Current user flows
1. **Найти обсуждение:** открыть раздел → список всех тем (категория, заголовок в 2 строки, автор, 💬 ответы, 👍 голоса, метка «Бекітілген») → нажать карточку. Поиска, фильтра, сортировки нет.
2. **Создать тему:** «Тақырып ашу» → окно: заголовок*, раздел/направление, текст* → «Жариялау (+30 XP, +15 🪙)» → окно закрывается сразу; в live тема появляется после ответа сервера (2–3 с), ошибки — системным `alert`.
3. **Ответить:** открыть тему → однострочное поле внизу → «Жауап беру» → поле очищается сразу.
4. **Оценить:** 👍 у темы и у ответа (переключатель); за свою — ничего не происходит.
5. **Чат:** «Жабық бөлмелер» → комната → сообщения → поле внизу → «Жіберу».

## 6. Strengths
- Сервер надёжно защищает игровую экономику: награды, лимиты, запрет голоса за себя, запрет менять модерационные поля не-модераторам — всё в базе.
- Честные надписи в чатах («Жабық чат», «Қолжетімділік: …»), без ложного E2EE; комната модераторов скрыта от участников и в UI, и RLS.

### F-01 — Тему в «Нетворкинг» (и любом новом направлении) создать нельзя
- **Раздел:** создание темы. **Severity:** High. **Тип:** Bug.
- **Описание:** список «Бөлім / Бағыт» строится из активных направлений (`activeDirections()`), а выбранный id пишется в `forum_topics.category_id`, который ссылается на `forum_categories`. Там нет `networking` (и не будет направлений, которые создаст админ). Вставка падает по внешнему ключу.
- **Где:** `ForumAndChatsView.tsx:52,75,496–505`; `live.ts:451–452`; `seed.sql:74–82`.
- **Воспроизведение (Verified, тестовая база, `claude-test`, 390 px):** «Тақырып ашу» → заголовок, «Нетворкинг және шай рәсімі», текст → «Жариялау» → `alert` «Енгізілген деректерді тексеріңіз.» → окно закрыто, введённое потеряно, тем в базе по-прежнему 1.
- **Почему проблема / влияние:** участник направления «Нетворкинг» не может начать обсуждение и не понимает почему; новые направления админа сразу «ломают» форум.
- **Рекомендация:** разделить «раздел форума» и «направление»: список разделов брать из `forum_categories` (он и так грузится), направление — отдельно или выводить; либо добавить недостающие разделы (данные в базе — нужно согласие владельца). При неизвестном разделе — понятное сообщение.
- **Сложность:** S. **Зависимости:** F-02. **Backend impact:** None (только фронт) или Low (строка в `forum_categories`). На production, вероятно, то же (тот же seed) — **не проверялось**.

### F-02 — Ошибка при отправке теряет набранный текст
- **Severity:** High. **Тип:** Bug / UX.
- **Описание:** `handleCreateTopicSubmit` закрывает окно и очищает поля сразу, `handleReplySubmit` очищает поле сразу — до ответа сервера. Ошибка показывается системным `alert`, текст пропадает. Нет индикатора отправки (в live 2–3 с), кнопку можно нажать повторно.
- **Где:** `ForumAndChatsView.tsx:58–79`; `AppContext.tsx` (`createForumTopic`, `replyToForumTopic` возвращают `void`, `runLive` делает `alert`).
- **Воспроизведение (Verified):** заголовок из 2 символов («Ок») → «Енгізілген деректерді тексеріңіз.», окно закрыто, текст потерян (база требует 3–200 символов, на клиенте проверки нет). Аналогично — ответ в закрытую тему (F-09), обрыв сети.
- **Рекомендация:** как в профиле (Phase 2.3.1): действия возвращают результат; окно/поле очищаются только при успехе; ошибка — внутри формы; «Жіберілуде…» на кнопке; клиентские лимиты (`minLength 3`, `maxLength 200/20000/10000`).
- **Сложность:** S. **Backend impact:** None.

### F-03 — Кнопка «Жауап беру» обрезана на телефонах
- **Severity:** High. **Тип:** Bug (mobile).
- **Описание:** в форме ответа однострочное поле (`flex-1`) не может сжаться меньше своей встроенной ширины, кнопка уезжает за край карточки (`overflow-hidden`).
- **Где:** `ForumAndChatsView.tsx:295–310`.
- **Воспроизведение (Verified, kz):** правый край кнопки за краем формы: 320 px — на 71 px, 360 — на 31, 375 — на 16, 390 — на 1; на 430 и шире — нормально. Скриншот `thread-320.png`.
- **Влияние:** на большинстве телефонов кнопка отправки обрезана или почти не видна (отправка возможна только клавишей Enter).
- **Рекомендация:** `min-w-0` у поля, на узких экранах — кнопка-иконка с `aria-label`; лучше многострочное поле (F-27).
- **Сложность:** XS. **Backend impact:** None.

### F-04 — Темы и комнаты не открываются с клавиатуры
- **Severity:** High. **Тип:** Accessibility.
- **Описание:** карточки тем и комнат — `div` с `onClick`, без `button`/`tabIndex`/`role`. Фокусируемых карточек — 0 на всех ширинах (Verified).
- **Где:** `ForumAndChatsView.tsx:143–177, 335–364`.
- **Влияние:** с клавиатуры или скринридером нельзя открыть ни одну тему и комнату — основной сценарий раздела недоступен.
- **Рекомендация:** карточки — `<button>` (или `<a>`), `aria-current`/`aria-selected` для выбранной; после открытия — фокус на заголовок темы.
- **Сложность:** S. **Backend impact:** None.

### F-05 — Абзацы склеиваются, длинные слова и ссылки обрезаются
- **Severity:** High. **Тип:** Bug / UX.
- **Описание:** текст темы и ответов выводится в `<p>` без `whitespace-pre-line` и без переноса длинных слов: переносы строк пропадают, длинная ссылка/слово выходит за карточку и обрезается (`overflow-hidden`), часть текста не видна.
- **Где:** `ForumAndChatsView.tsx:234–236, 284–286, 433` (сообщения чата — то же).
- **Воспроизведение (Verified):** тема с «Бірінші абзац.\n\nЕкінші абзац…» и длинной ссылкой → один абзац, конец ссылки и длинного слова не виден (`long-320.png`). Горизонтальной прокрутки страницы при этом нет.
- **Рекомендация:** `whitespace-pre-line break-words [overflow-wrap:anywhere]`; ссылки — по желанию отдельно (без HTML из текста).
- **Сложность:** XS. **Backend impact:** None.

## 15. Security concerns
- **S-1 (Low, нужно решение владельца):** автор может удалить свою тему через API (RLS `topics_delete`), а ответы других участников удаляются вместе с ней (`on delete cascade`). В интерфейсе удаления нет, но API позволяет. Варианты: удалять только модератору / «мягкое» удаление (скрытие) / запрещать удаление темы с чужими ответами. Backend impact: Medium. Ничего не менялось.
- **S-2 (Low, решение владельца):** автор может менять текст темы/ответа после чужих ответов и голосов (RLS `topics_update`/`replies_update`), без пометки «изменено» — возможна подмена смысла обсуждения. Backend impact: Low.
- Не найдено проблем с модерационными полями (защищены триггером), голосами за себя (триггер), доступом к комнатам (RLS) и наградами (только сервер).
